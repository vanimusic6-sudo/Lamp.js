# Amedia 5.6 — критический аудит интерфейса, ТВ и воспроизведения
**Дата:** 16 ноября 2026  
**База:** `main` @ `0a12fb2f` (Amedia 5.5.0)  
**Проверяемый код:** `amedia-android.js`; тесты: `tests/amedia-v5.test.cjs`  
**Статус:** предварительная реализация в `feature/amedia-ui-5-6`; реальный ТВ-тест всё ещё обязателен.

## Метод
Трассированы точки входа Amedia в карточку фильма/сериала, компонент `amedia_hub_v6`, нормализация native playlist, очередь Skaz, состояние `Lampa.PlayerPlaylist`, `Timeline`, автоподбор озвучки, картинки и настройки. Изучен открытый код Android-LAMPA `MainActivity.kt`: https://github.com/lampa-app/LAMPA/blob/main/app/src/main/java/top/rootu/lampa/MainActivity.kt. Никаких потоков Skaz/токенов в отчёте нет. Тесты — модели Lampa, а не физический ТВ.

## Критические дефекты / исправления

### P0 — встроенный плейлист Lampa сам себя обнулял — ИСПРАВЛЕНО в коде
`prepareLazyInnerQueue()` формирует очередь, где `item.url` — функция асинхронного получения свежего подписанного потока. `checkNativePlaylist()` до исправления фильтровал каждый элемент по `typeof item.url === 'string'`. В результате все ленивые записи удалялись, `data.playlist` пропадал. Добавлен отдельный путь валидации для функции-URL в режиме `inner`, а текущая серия распознаётся по `season/episode`, не по URL. Новая регрессия проверяет всё это на сериале из двух сезонов.

### P0 — нельзя честно обещать полную рабочую очередь стороннему Android-плееру — ОТКРЫТО, БЕЗОПАСНЫЙ FALLBACK
`queuePlan()` для Android планировал только две следующие серии, `makeQueue()` создаёт короткие подписанные URL. Android-LAMPA получает JSON и преобразует список в нативные элементы; приложение передаёт внешнему player Intent один общий набор HTTP-заголовков из корневого `jsonObject.headers` (см. `MainActivity.kt`, `prepareHeaders`, `runPlayer`, `configurePlayerIntent`). Подписанные ссылки разных эпизодов требуют нового сеанса/заголовков/иногда балансера. Поэтому следующий HLS-манифест может падать даже при валидном URL. В 5.6 сохранены per-item headers в JS, но **стандартный Android мост их не использует**. В текущей реализации несовместимые записи отбрасываются перед Android-handoff, чтобы не отправлять заведомо неисправную очередь. Это улучшение надёжности одиночного запуска, **не реализация всей Android-очереди**.
Для настоящей бесконечной очереди нужен нативный контракт: список метаданных всех серий + запрос `resolve(episode_id)` перед КАЖДЫМ переключением и передачей отдельного `headers`/времени жизни, ответ/таймаут, обновление записи по текущему индексу и обработка ошибок без прыжка через сериал. Изменения только этого JS-плагина для стандартного Android-LAMPA недостаточно.

### P1 — постеры серий исчезали при недоступном image helper — ЧАСТИЧНО ИСПРАВЛЕНО
`imageUrl()` ранее мог вернуть пустую строку для валидного TMDB path при отсутствии `L.Api.img`/`L.TMDB.image`. Добавлен fallback на официальный `https://image.tmdb.org/t/p/...`. Сохраняются резервный кадр/постер и номер серии, когда конкретное изображение отсутствует. Недоступность самого TMDB/CDN в сети устройства этим не решается. Проверка на ТВ обязательна.

### P1 — управление с пульта и фокус при обновлениях — ЧАСТИЧНО ИСПРАВЛЕНО
Экран после `scroll.clear()` заново рисовал весь DOM и сразу фокусировал первую кнопку. События загрузки стороннего каталога вызывают `hub.redraw()`, поэтому пользователь мог терять прокрутку и попадать в начало списка. Сохраняется `data-am-key` текущего элемента, после перестройки восстанавливается фокус и прокрутка через `L.Scroll.update()`. Длинные сезоны рисуются по 32 позиции с кнопкой «Показать ещё». Нужен аппаратный тест разных версий Lampa TV и пульта.

### P1 — автоподбор перевода считал непрерывность не той серии — ИСПРАВЛЕНО
При рендере всех карточек `topVoice(ctx, ep)` получал `ctx.episode` от ранее выбранной серии, а не от `ep`. `voiceContinuity()` дополнительно сканировал дерево для каждой озвучки. Теперь перед выбором переводов устанавливается точный контекст эпизода, затем восстанавливается; индекс доступных эпизодов кэшируется по дереву. Значимость субъективных студийных весов не преувеличивается: это *эвристический приоритет*, не объективный рейтинг качества.

### P2 — дублирующиеся CSS-правила и визуальный шум — ИСПРАВЛЕНО
В `installHubStyle()` подряд шли два несовместимых слоя оформления одних и тех же классов. Заменены на единую схему для ТВ и мобильного экрана; одинаковое выравнивание обложек, компактная сетка, фокус без тяжёлых анимаций. Вынесены состояния «Не начато», «Смотрю», «Просмотрено» и маркер текущей серии; под карточкой отдельно показан тип перевода. Значения синхронизированы с Timeline, а не с самим фактом выбора карточки.

### P2 — настройки очереди нарушали принцип «просто смотреть» — ИСПРАВЛЕНО
Убраны переключатели `queueDepth` из общих настроек и экрана сериала: раньше пользователь мог случайно отключить даже ленивую очередь Lampa. Сохраняется автоматическая логика согласно типу плеера. Диагностика очередей и HLS больше не загромождает обычный экран, видна только при включённой диагностике. В настройках сериала есть необязательное «Скрывать просмотренные» и сброс качества/озвучки для этого названия.

### P2 — флаг Resume прятал статус просмотра — ИСПРАВЛЕНО
Раньше `episodeProgress()` показывал 0 при выключенном автоматическом продолжении; отключение *автостарта с позиции* не должно обнулять графический статус. `timeline(..., forDisplay:true)` читает имеющиеся отметки даже когда воспроизведение начнётся с нуля.

## Оставшиеся риски, не выдаваемые за решённые
- **Android full-playlist:** нужен отдельный API в Android-LAMPA/внешнем player; невозможность per-item headers и истечение подписанных ссылок не устраняются JS-фильтрацией. Нельзя объявить «все серии работают» до такого механизма и ТВ-теста.
- **Первая серия во встроенном плеере ТВ:** восстановление lazy-очереди исправляет явную ошибку очереди, но не доказывает, что WebView телевизора умеет этот HLS, CORS и требуемые заголовки. Диагностика должна записать категорию отказа, без экспорта токенов/URL.
- **Обложки:** fallback не лечит DNS/доступность CDN, политику mixed-content и ограниченный Android WebView. Нужны логи `img.onerror`/реальные адреса API (без пользовательских токенов), измерение загрузки.
- **Монолит 300КБ:** обфусцированное ядро Skaz и понятный UI-клиент в одном файле затрудняют независимые релизы и локальный аудит. Извлекать и перестраивать оригинальный transport без доказанной эквивалентности слишком опасно; следующий этап — отдельные интерфейсы для UI, model, provider и bridge, без переизобретения протокола.
- **Глобальные хуки:** `setupVerifiedAutoNext()` меняет общий `playlist_next` на время внутреннего проигрывания и возвращает значение. Гонки с другим плагином или прерыванием WebView остаются потенциальным риском; в CI есть тесты отмены сессии, но нет мультиплагинового стресс-теста.
- **E2E:** смоделированные Lampa/Android API не заменяют тесты MX/ViMu/Just+ и телевизионной сборки Lampa. Особенно важны долгий HLS, переход через границу сезона, возврат к старой серии, пульт, отсутствие обложек, пробуждение из фона.

## Критерии приёмки на ТВ
1. Открыть сериал с 80+ сериями: пролистать до конца списка с пульта, сменить сезон, вернуться и повторить после загрузки метаданных; фокус не теряется.
2. Открыть 1, 2, 3 и последнюю серию встроенным Lampa, проверить качество, переход, возврат к ранее просмотренной серии и обновление ссылки.
3. На Android проверить первую серию без ошибок; не выдавать неработающие 2–3 за доступную очередь. Полноценная непрерывная внешняя очередь остаётся отдельной задачей native bridge.
4. Открыть сериал с пустыми TMDB stills: видны резервное изображение/номер серии, никаких пустых серых карточек.
5. Проверить разные озвучки, отключить Resume (прогресс остаётся видимым) и включить «Скрывать просмотренные».

## Автоматические проверки
Рабочий процесс `.github/workflows/amedia-check.yml`: `node --check amedia-android.js` и `node --test tests/amedia-v5.test.cjs`. Проверки покрывают загрузку сериалов, ленивую очередь, сериал по сезонам, защиту от перехода на неправильную серию, Android headers, качество, выбор переводов, прогресс и некоторые сценарии UI. Факт зелёного CI не равен проверке реального ТВ.
